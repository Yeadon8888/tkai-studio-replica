# 产品首帧路线

当视频模型仅凭产品参考图仍反复生成错误产品细节、标签乱码或不稳定外形时，用首帧路线。它先用图片编辑模型把真实产品放进简报的 0–3 秒场景，再把这张图作为视频的第一参考图。产品参考图仍保留为第二张。

不要把它当作所有简报的默认步骤。产品本身已经稳定、只需验证创意或动作时，直接图生视频更省费用。需要严格对比时，保留原简报和原成片作为对照组，首帧路线使用 id 后缀 `-kf`，不覆盖原数据。

## 输入与产物

```bash
python3 kit/keyframe.py \
  --project <运行目录> \
  --brief <原简报.json> \
  --product-reference <产品参考图>
```

程序优先使用简报的 `keyframe.prompt`。没有该字段时，从原 `prompt` 提取 0–3 秒描述。首帧写入 `<运行目录>/keyframes/<id>-kf.png`，并用 `ffprobe` 核验尺寸与简报 `aspect_ratio` 一致。新简报写入 `<运行目录>/briefs/<id>-kf.json`。

## 费用与账本

每个首帧是一次图片编辑付费调用。生成前先用 `products.can_spend` 检查该品剩余预算，并把运行目录登记到该品。账本写一条 `kind: image`：`IMAGE_PRICE_CNY` 有值时记单张估价，留空时 `estimate_cny` 为 `null`。视频生成和自动评审仍按原有账本规则记录。

上游报错、超时或回包无法解析时不自动重试，不换模型。先核对账本和上游任务状态，再由人决定是否进行新的付费调用。

## 风险

- 图片编辑仍可能改变产品标签、比例或手部细节；生成后要先人工看首帧，再提交视频。
- 为了得到简报的精确比例，程序可能对图片做中心裁切。首帧提示词应把产品和手部放在中央安全区。
- 首帧只约束开头外观，不保证视频后续帧不变形。仍需保留第二张产品参考图，并在提示词中明确两张图的角色。
- 自动评审若记录 `mode: video_fallback`，说明理解模型没有真正读到整条视频；结果来自抽帧回退，交付时必须如实标注并附该次 `prompt_tokens`。
