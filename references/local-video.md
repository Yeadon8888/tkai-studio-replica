# 本地视频的处理方法（写给 agent 的规则）

## 什么时候用

用户给了一个本地视频文件（例如微信里收到的 `.mp4`）作为对标或参考。

## 默认做法：整条上传 → 整条拆解 → 删除

1. **确认授权**：用户给本地文件，本身就表示同意把它上传到公网做拆解。只在 `.env` 的 `MEDIA_UPLOAD=github_temp` 时执行；如果是 `off`，先问用户。
2. **上传**：`kit/media_host.py` 把视频放进用户自己 GitHub 账号下的专用公开仓库（`MEDIA_HOST_REPO`，默认 `Yeadon8888/studio-media-temp`），路径是 `clips/<sha256 前 16 位>.<扩展名>`。
   - 只用 `gh` 命令行和用户已登录的 GitHub 账号。
   - 不用网页上的访问码，也不用别人的图床。
   - 不上传封面、日志或其它文件。
3. **拆解**：把公网直链交给 Gemini（`MODEL_BREAKDOWN`），用整条视频读七个维度、风格、是否有人、证据（带时间码）。这是最完整的做法。
4. **删除**：拆解结束后立即删除临时文件，并用 HEAD 请求确认不可访问。删除结果写入 `media/media_log.jsonl`。
   - 删除失败时，告诉用户：文件还在、地址是什么、需要人工删除。
5. **记录**：拆解结果里写 `source: local_upload_whole_video` 和 `media_deleted`。以后看板可以据此区分来源。

## 不这样做的情况

- **抽帧（`MEDIA_UPLOAD=off`）**：只在用户禁止上传时使用。抽帧会丢动作和细节，结果里要注明"细节不完整"，不能用来判断风格细节或产品细节。
- **不是对标用途的视频**（例如用户自己的产品实拍原片）：不上传，先问用户。

## 常见问题

- **文件太大**：超过 90MB 不上传。先让用户压缩，或者只截取需要的片段。
- **同一个视频再次拆解**：文件名由内容的 sha256 决定，同一内容会复用同一路径。
- **Gemini 读不了**：用 `loop.gemini` 的 `video_url`，已在 0.6.0 验证过 raw.githubusercontent 的直链可以读。如果换了托管方，先用 `gemini` 测一次。
