# studio 接入视频增长中台：对接设计（草案，待用户批准）

日期：2026-11-14 · 作者：Claude · 状态：草案，未授权开发与上线

## 一句话判断
不新建平台，而是把 studio 做成中台的一个"制作执行机"：中台负责人、组织、项目、成片版本、审核、发布和数据（已有，复用）；studio 负责拆解、写脚本、生成、评审和神韵打分（Python + ffmpeg + Hypit，Cloudflare Workers 跑不了）。人在中台页面里做确认，结果回流到 studio 做校准。

## 执行机协议（扩展现有 agent 令牌）
- 新增令牌权限：`jobs:read`、`jobs:write`、`checkpoints:write`（沿用 `uploads:write`、`reviews:read`）。令牌仍绑定组织与运营角色，服务端校验组织范围。
- 新接口（Worker）：
  - `GET /api/agent/production-jobs`：本组织待执行的制作请求（内容项、对标样本、档位、条数、预算上限）。
  - `POST /api/agent/production-jobs/:id/claim`：领取，带租约（例如 30 分钟），过期可被重领；幂等键防重复。
  - `POST /api/agent/production-jobs/:id/checkpoint`：执行机遇到确认节点时上报（脚本、预算），中台生成内部待办。
  - `GET /api/agent/checkpoints/:id`：读取人工决定（批准/驳回/要求修改 + 原因 + 修改内容）。
  - 成片上传沿用 `POST /api/v3/uploads`，附内部证据：对标、神韵逐项结果与分数、专家问题、花费、模型。证据只给内部角色看。
- 主记录归属：项目、版本、审核、发布事实、人工决定以中台 D1 为准；执行机本地文件只是工作缓存与账本。花费同步到中台作为内部成本，不进客户视图。

## 最强的反对意见与放弃条件
- **神韵指标还没被验证**：如果 R13 之后人判与 `essence_score` 的一致率很低，平台只会把不可靠的分数搬给更多人看。放弃条件：P1 前至少 10 条人工判定，一致率低于 70% 就先修指标，不进 P2。
- **两套状态打架**：执行机和中台都记"进度"。缓解：中台为唯一主记录，执行机只上报；放弃条件：出现无法自动对齐的状态冲突，则退回只上传成片（P1）。
- **执行机在你的 Mac 上**：关机即停。P1 可接受；量起来再换服务器。
- **客户可见性**：任何内部证据泄露给客户都违反中台红线；P1 验收必须包含客户角色越权测试。
- **成本**：每条成片的视频费用不会因为上平台而下降；平台价值在于减少沟通和返工，需按中台元提示词记录交付耗时与返工次数作对照，没有对照时写"尚未测量"。
